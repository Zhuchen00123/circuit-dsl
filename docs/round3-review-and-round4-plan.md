## 3. 待修问题

### R4-01 / P1：非法中间值被掩盖，测量返回正常数字

定位：`crates/circuit-results/src/expr.rs` 中 `eval_product`、`eval_sqrt`、`eval_elementwise`。

在正常分压电路的 OP 实验中：

```ruby
derive :invalid, expr: sqrt(-1)
measure :masked, max: min(sqrt(-1), 2)
```

实际结果：运行退出码 0，测量为 2，派生信号 JSON 值为 null，没有诊断。将 `sqrt(-1)` 换成 `1e308 * 1e308`，也会成功输出测量 2 和 null。

原因：sqrt 未验证定义域；乘法没有非有限结果检查；min/max 可以把非法中间值掩盖。因此只检查表达式的最终结果不足以修复。

要求：

- 对表达式输入、每个运算节点及运算结果实施一致的有限值与定义域策略；实数和复数都覆盖。
- sqrt 负值、算术溢出、除零、非法对数等返回结构化诊断，不能被外围 min/max 或归约掩盖。
- 诊断包含 derive/measure 名称、分析身份、可用的样本索引与轴坐标；标量表达式说明其为标量。
- 能在 check 确认的常量错误尽早拒绝；依赖信号的错误必须在 run 拒绝。
- 不使用 epsilon、截断、饱和或跳过样本制造成功结果。
- 表达式失败时不得为本次失败执行新写成功结果文件；不要删除用户已有输出。
- 原始后端数据的非有限值导出策略与表达式错误策略分开定义，避免无意改变全部 Dataset API 的契约。

### R4-02 / P2：量纲指数溢出导致用户输入触发 panic

定位：`crates/circuit-core/src/units.rs:47` 起的 Dimension 算术及其动态调用方。

复现：derive 表达式由 128 个 `v(:vin)` 通过乘号连接。`cdsl check` 退出 0；debug 版 `cdsl run` 在 units.rs:49 报 `attempt to add with overflow`，退出 101。

要求：用户可控制的量纲运算使用受检算术，超出表示范围返回诊断。不能仅扩大整数类型、使用 wrapping 或依靠 catch_unwind。静态常量构造与动态求值可以保留不同接口，但所有 DSL 可达路径都要受保护。覆盖乘、除以及存在的幂调用方；debug/release 均不得 panic 或静默回绕。此次只实测了 debug panic，未把 release 行为作为已验证结论。

### R4-03 / P2：会话导出丢弃警告

定位：`crates/circuit-session/src/execute.rs:984` 的 `write_datasets`；`crates/circuit-results/src/export.rs` 的文本便捷接口。

导出器已有 `to_csv_with_diagnostics` / `to_json_with_diagnostics`，但会话写文件调用仅返回文本的接口，丢失非有限值警告。上述 R4-01 复现同时证实 CLI 未告知用户 null 的原因。

要求：保留导出诊断并传到 CLI/REPL 的用户可见输出，明确 JSON 内诊断与调用返回诊断的关系；同时导出两种格式时避免重复刷屏。使用直接构造含非有限数据的合法 Dataset 测试，确保 R4-01 修好后仍能独立覆盖这个路径。

## 4. 阶段 A：正确性修复与验收

先补能在当前版本失败的回归测试，再修上述三个问题。验收矩阵：

| 场景 | 必须观察到的行为 |
|---|---|
| sqrt(-1)、负信号开方 | 结构化错误，无成功测量 |
| min(sqrt(-1),2)、max 的同类嵌套 | 非法中间值不能被隐藏 |
| 1e308*1e308、嵌套 min/max | 溢出诊断 |
| 非有限复数分量与复数运算溢出 | 统一错误策略 |
| 128 个电压探针相乘、量纲减法边界 | check/run 诊断，无 panic、无回绕 |
| 原始 Dataset 含 NaN/Inf 的 CSV/JSON 导出 | 保留约定空值格式，同时可见警告 |
| CLI 与 REPL 相同表达式 | 数值、错误类别一致 |
| 同一实验先有效 derive 后非法 derive | 本次失败不产生成功输出文件 |
| RC 增益、功率、多分析绑定、隐式探针、重采样 | 原有行为保持正确 |

量纲边界至少用定向 release 测试验证一次。完成工作区测试、Clippy、fmt；独立 reviewer 确认 R4-01 至 R4-03 闭环后才能开始阶段 B 的代码实现。

## 5. 阶段 B：参数 DAG

目标：参数值按依赖关系计算，允许同作用域前向引用；循环依赖明确报错；参数对拓扑的间接影响在 check 阶段可发现。

### 5.1 先冻结语义

编写 `docs/review-evidence/round4/design-contract.md`，基于当前解析器、作用域、实例覆盖与 REPL 行为，明确：

1. 参数的作用域身份与名称解析规则，不能仅用裸字符串作为跨作用域节点 ID。
2. 重复定义、遮蔽、实例覆盖、会话覆盖的有效定义选择顺序，保留已文档化兼容行为。
3. 先确定有效定义再建立相应依赖图，不能让被覆盖的无效默认表达式误伤有效覆盖；对确需校验的声明另行说明。
4. 前向引用、未知名称和依赖环的不同诊断；自环与多节点环应输出闭合路径及相关源位置。
5. override 后哪些依赖必须重算，REPL 失败是否保留原状态；推荐沿用现有事务式成功提交行为。
6. 拓扑使用点包括当前支持的条件展开、数量展开等；从实际 AST/IR 取证，不假定尚未实现的语法。

### 5.2 实现范围

- 收集参数声明与引用边，稳定拓扑排序并按依赖求值。
- 使用现有表达式/数量求值规则，不另建一套单位系统。
- 传递传播拓扑依赖：若拓扑依赖 a，a 依赖 b，扫描 b 也必须被识别。
- `check` 拒绝会改变拓扑的参数扫描，并报告“扫描参数 → 中间依赖 → 拓扑使用点”的解释路径。
- 普通元件数值参数扫描保持可用；同名局部参数不能产生误报。
- 运行时已有拓扑防线保留，不能因提前检查而移除。
- 参数 DAG 不扩展为 derive 之间的引用，不引入跨分析计算。

### 5.3 必须验收

- 前向引用、多层链与菱形图计算正确，重复运行顺序确定。
- 未知名称、自环、多节点环分别得到明确诊断和源位置。
- 嵌套实例同名参数互不污染，覆盖后所有相关派生参数更新。
- REPL 修改基参数后结果更新；失败更新不污染下一次成功执行。
- 直接和间接拓扑扫描都在 check 被拒绝；无拓扑影响的扫描成功。
- 扫描点的数值与手工独立计算一致，不只断言退出码。
- 第 2/3 轮的瞬态网格、原始数据测量、分析绑定、导出集合行为保持通过。
