## 4. 第 3 轮主目标：结果表达式进入 DSL、CLI 与 REPL

这是目前最有用户价值的下一步：用户能直接求传递函数、增益与功率，不必导出 CSV 后自行计算。

现有 `circuit-results/src/expr.rs` 已有求值器，`circuit-core/src/plan.rs::MeasureRequest.target` 仍是 Probe。应连接现有能力，而非新建第二套表达式执行引擎。

### 4.1 范围

- 表达式支持电压/电流探针、数值常量、正负号与四则运算。
- 复用已有 abs 与增益 dB 语义。
- 表达式结果保留单位、实/复数类型和分析坐标。
- 支持表达式测量与命名派生信号导出。
- 文件模式与 REPL 使用同一执行路径。
- 保持现有直接探针 save/measure 语法兼容。

建议的目标语法如下；实施者需先核对现有解析器，并把最终语法写入规范，不能将示例误称为已支持：

```ruby
experiment :response, circuit: :rc_filter do
  ac from: 100.Hz, to: 100.kHz, points_per_decade: 40

  derive :gain, expr: v(:vout) / v(:vin)
  derive :gain_db, expr: gain_db(v(:vout), v(:vin))
  measure :peak_gain, max: abs(v(:vout) / v(:vin))
end

experiment :power, circuit: :rc_filter do
  tran stop: 1.ms, max_step: 100.ns, output_interval: 10.us
  measure :avg_power, avg: v(:vin, :vout) * i(:r1)
end
```

首期派生信号不互相引用，避免在本轮额外引入第二套依赖图。函数名和输出名称属于不同语境，应明确区分。

### 4.2 必须先确定的接口

1. **表达式 IR 归属**：让共享计划层描述已解析探针与表达式；求值器属于 results。禁止 core 反向依赖 results 造成循环依赖。
2. **分析绑定**：新增 derive 与复合表达式在单分析实验中允许省略绑定；多分析实验通过明确的 analysis_id 绑定，无法唯一确定时报告歧义，不静默挑选第一个结果。采用 `analysis: :ac1` 形式并在规范中固定。兼容例外：已有不带 analysis 的直接探针 measure 保留已文档化的 TRAN → AC → DC → OP 选择顺序；同类型的先后规则也应固定。将选择结果记录到测量元数据，并允许通过 analysis 覆盖旧规则，不能为新能力直接破坏旧示例。
3. **隐式探针依赖**：表达式使用的探针自动进入后端读取集合，不要求另写 save 才能求值；输出集合与内部依赖集合分开，避免导出无意要求的原始信号。
4. **数值执行顺序**：后端原始数据 → 表达式求值 → 测量 → 展示/导出重采样。非线性表达式必须先求值，再对派生信号重采样，不能交换运算顺序而不说明。
5. **结果身份**：使用明确的分析身份和信号身份，不通过宽松字符串猜测把表达式绑定到错误数据集。

### 4.3 错误契约

- 加减量纲不匹配、dB 输入比值非无量纲、未知探针和未支持电流，应尽可能在 check 阶段报错。
- AC 复数没有默认大小顺序，max/min 要求实数表达式，例如 abs(gain)。
- OP/DC/AC 不能使用要求时间积分的 avg/rms。
- 禁止跨分析、跨时间轴隐式逐项运算。
- 首期除零和 dB(0) 使用明确的测量/表达式错误，带分析和样本坐标；若沿用现有另一种非有限值策略，必须统一规范、导出和退出码，不能静默得到看似成功的 null。
- 当前 evaluate_measures 会在某项求值失败后继续尝试其他分析，最终可能不返回该测量。新实现必须区分“分析不适用”和“所选分析执行失败”；所有候选均不适用或所选分析失败时返回诊断，不可默默丢失用户请求的测量。
- 大数组运算遵循结果规模限制，避免不受控广播或复制。

### 4.4 验收用例

1. RC 截止频率处，gain 约为 `0.5 - 0.5j`，幅度约 0.70710678，dB 约 -3.01029996。确保实际采样包含截止频率，否则在实际频率上计算参考值。
2. 电阻功率 `v(p,n) * i(r)` 与 `v(p,n)^2/R` 对照为正；首期语法不支持幂运算时参考值在测试代码计算。
3. 改变 output_interval，表达式测量结果保持一致；导出点数按输出契约变化。
4. 没有显式 save 的表达式仍能获得所需探针。
5. 同一文件多个分析时，明确绑定有效；新增 derive/复合表达式省略绑定的歧义被拒绝；旧直接探针 measure 的兼容选择规则有专门测试。
6. 单位错误、除零、未知节点、不可用电流、复数直接 max、跨轴组合均有负例。
7. 文件运行和 REPL 运行数值、诊断及导出一致。
8. 既有 457 个测试保持通过，新增测试数量如实报告；不固定最终数量。

## 5. 团队实施安排

- 主代理先冻结表达式 IR、分析绑定与输出字段契约，负责 core 公共类型和最终整合。
- 前端 worker：AST/解析/语义与隐式依赖收集，唯一拥有相关 frontend 写集。
- 结果 worker：现有求值器适配、单位/复数/错误策略与独立数值测试。
- 会话 worker：待公共契约冻结后，连接统一执行路径与重采样顺序。
- QA worker：独立 CLI/REPL 端到端测试，使用独立测试文件。
- 独立 reviewer：检查依赖方向、分析绑定、数值运算顺序与资源边界。

不要同时启动参数 DAG 实现，它会与前端表达式任务争用 elaborate.rs、作用域和计划结构。可以独立做只读设计，留下一轮实施。

## 6. 后续路线

1. 本轮：结果表达式、派生信号与测量闭环。
2. 下一轮：参数 DAG、环诊断、拓扑依赖传播与 check 阶段拒绝拓扑扫描。
