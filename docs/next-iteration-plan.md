# 本轮检阅与下一步计划

## 1. 结论

上一轮完成了浮空用例纠正、匹配解析解和数值证据改进，可以保留这些成果。下一轮优先解决瞬态用户参数的语义问题，再补结果表达式与参数依赖图。

本轮为检阅与计划，没有修改产品代码。复现输入和结果位于 `target/next-round-review/`，属于本地验证产物。

- `cargo run --quiet --manifest-path _probe/Cargo.toml --bin probe`：6 个准入用例通过；其中较粗步长配置仍显示 NOT-MET，不能理解为所有配置均通过。

## 3. 确认的问题

### P1：输出间隔会改变用户声明的激励波形

位置：`crates/circuit-backend/src/thevenin.rs::map_analysis` 的 TRAN 分支，约第 771 行；`crates/circuit-core/src/plan.rs::TranSpec`。

目前将 `output_interval` 直接映射成后端 `Tran.step`，后端会以该值作为 PULSE 上升/下降时间下限。未设置时又使用分析区间长度除以 1000，因此改变仿真窗口也可能改变原始输入波形。

本次通过真实 CLI 复现：RC 电路 R=1 kohm、C=100 nF；输入从 0 V 升到 1 V，声明 rise=10 ns；两次均使用 stop=2 us、max_step=1 ns。

| output_interval | 约 50 ns 的实际返回时间 | v(vin) | v(out) | 返回点数 |
|---|---|---|---|---|
| 1 ns | 49.5 ns | 1 V | 0.0004449006 V | 2015 |
| 100 ns | 50.02375 ns | 0.5002375 V | 0.0001250979 V | 2015 |

两次时间点并不完全一致，但声明的 10 ns 上升沿在两个采样时刻都应已经结束；第二次输入只有约 0.5 V，明确证明用户激励被改变。

现有 `declared_rise_below_output_interval_is_clamped_to_the_output_step` 测试记录的是后端行为，不应被当成最终产品语义的正确性证明。参考模型匹配实际执行波形是数值审计进步，但产品还需要兑现用户声明的波形。

### P2：非法 output_interval 被静默替换

位置：`crates/circuit-dsl/src/elaborate.rs::tran_spec`，约第 2446 行；后端映射的 `.filter(|s| *s > 0.0)`。

前端只验证量纲，没有像 max_step 一样要求 output_interval 大于零。后端过滤非正数后回退默认值。

本次将复现文件中的 output_interval 改为 -1 ns，`cdsl check` 返回 0，没有诊断。应明确拒绝显式传入的非法值，不能将错误配置解释为使用默认设置。

### 已知精度限制：运行中的源断点

上一轮已如实记录延迟脉冲断点附近的精度超限。此次重跑 `_probe` 也观察到：较粗步长下存在超限点，而细步长基线通过。

这不是“任何配置都错误”的证明，也不能靠已有 413 个测试通过来宣称已解决。产品回归中的 RC 仍主要从 delay=0 起步，应增加非零延迟、下降沿和重复周期用例。

## 4. 下一轮实施顺序

### 任务 A：修正瞬态参数契约（最高优先级）

目标：输出采样、求解步长和激励波形三个概念分开。

实施步骤：

1. 在前端与公开后端输入边界校验 output_interval 为有限正值，显式错误不得回退默认值。
2. 确立 `max_step` 仅约束积分步长，`output_interval` 仅控制输出采样。
3. 设计并验证后端 step 的独立映射，使显式 PULSE rise/fall 不因输出间隔或 stop 改变；处理多个源、默认边沿及数值下限，不能简单将 step 设为零。
4. 若后端暂不能忠实执行某组源参数，先返回明确能力错误；不能静默展宽边沿。
5. 输出间隔通过求解后的独立重采样阶段实现，固定起点、终点、插值规则和最大点数；不要把粗输出采样混入原始测量积分。尚未实现重采样前可明确拒绝该选项，不能继续接受但改变输入。
6. 原始求解数据、重采样数据与实际求解配置在结果元数据中可区分。

验收：

- 本文 10 ns 边沿反例修复；改变 output_interval 不改变原始源波形与物理解。
- 延长 stop 时重叠时间区间的激励保持不变；数值结果在合理误差内一致。
- output_interval 为零、负数、非有限值均在相应输入层拒绝。
- 重采样输出网格符合契约、没有越界外推、输出规模受限；None 保留原始求解网格。
- 保留底层行为测试，但产品验收必须按 DSL 声明值比较，不再以静默夹取后的边沿为最终标准。

主要文件：`circuit-core/src/plan.rs`、`circuit-dsl/src/elaborate.rs`、`circuit-backend/src/thevenin.rs`、结果/会话层相关模块及对应集成测试。

### 任务 B：把运行中断点纳入产品精度回归

依赖：任务 A 的源与采样语义固定。

1. 加入非零 delay、有限 rise/fall、至少两个周期的 PULSE 用例。
2. 核对断点定位和重启步长，分别变化最大步长与后端实际支持的容差。
3. 以独立解析解或独立参考验证断点前后，不能删掉误差最大的样本。
4. 如果需要后端修复，提供最小复现并评估局部适配、固定版本补丁或上游修复；不直接重写求解器。
5. 无法保证任意粗步长精度时，明确数值配置适用范围。不要把某个 RC 电路上的安全步长比值冒充所有电路的精度保证。

验收：选定且公开的配置下全区间满足既定判据；不满足的配置保留为限制/诊断实验，并在报告中与必过回归区分。

### 任务 C：接通结果表达式（优先功能增量）

当前 `circuit-results/src/expr.rs` 已有表达式求值器，而 `MeasureRequest.target` 仍是 Probe。补齐 DSL → 语义表达式 → 依赖探针 → 会话执行 → 导出的路径。

第一批能力建议：

- `v(:out) / v(:in)`、`v(:out) * i(:r1)`。
- 实/复数运算、幅度与增益 dB，命名沿用已有实现并在语言规范固定。
- 自动收集表达式所需探针，不要求用户另写 save 才能测量。
- 多分析绑定明确：测量属于哪项分析，错误在 check 阶段尽可能发现。
- 复数没有默认大小顺序；AC max/min 应要求显式 abs 等转换。
- 除零、单位错误、跨坐标轴组合和 OP 上的时间平均给出确定诊断。

层间依赖必须保持单向：不要让 circuit-core 为复用求值器而反向依赖 circuit-results。主代理先确定共享表达式 IR 的归属，再并行实现。

验收示例：RC 截止频率处幅度比约 0.7071、增益约 -3.0103 dB，电阻耗散功率为正；文件模式与 REPL 行为一致。

### 任务 D：参数 DAG 与拓扑参数传播

1. 收集同作用域参数定义，建立依赖图，支持前向引用。
2. 保持现有实例/实验/扫描覆盖顺序；先确定有效定义，再求值。
3. 环诊断包含依赖链与定义位置；未知名称和环是不同错误。
4. 拓扑依赖沿派生参数传播，让 check 提前拒绝首期不支持的拓扑扫描。
5. 保留运行时逐点拓扑比较作为第二道检查，不因静态分析新增而删除。

验收：前向引用、覆盖影响派生参数、子电路作用域隔离、完整环诊断、间接拓扑依赖和既有扫描回归全部覆盖。

## 5. 并行安排建议

- A 与 B 构成先后依赖，不能对同一后端文件并行写入。
- C 与 D 可以提前分别做只读设计和独立测试方案；二者都会涉及 elaborate.rs 和公共计划类型，必须先冻结接口再划分写集，不能直接按功能名各自开工。
- 下一轮主目标建议只定为 A+B，完成后再开 C；D 可作为随后一轮。这样每轮都有明确产品价值与验收结论。
- 文档清理、UTF-8 BOM 支持、JSON 单独导出 QA 可安排为低优先级独立任务，不能挤占瞬态正确性修复。
- 不重复修已经通过的相位测试与浮空正例，不为旧 gate 报告中的已修哈希问题再开任务。

## 6. 下一轮结束条件

1. 激励波形不再被输出参数静默修改。
2. 非法瞬态选项被明确拒绝。
3. 延迟源断点有真实产品路径回归与有依据的精度范围。
4. 全量 workspace 测试、独立 probe、适用的 fmt/clippy 完成，按真实结果报告。
5. 更新语言规范、后端映射说明和用户可见限制；证据冻结与最终代码对应。

本计划不自动授权切换后端、发布或大范围重构；实现者应优先采用最小且可验证的改动。
